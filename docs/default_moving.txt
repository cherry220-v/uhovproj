Как работает behavior "default_moving" для монстра
Поля конфига:
    "default_target": "4f.420" - Дефолтный таргет это игрок. При достижении цели атакует (изменение состояния на atacking) и возвращается на стартовую позицию спавна (изменяя состояние на returning). После monster startRoom состояние на "idle"
    "agression": 6 - Увеличивает шанс 5*agression к тому что монстр выберет целью лестницу
    "spProgression": 10 - Увеличивает шанс каждый час к тому что монстр выберет целью специальное событие если такое доступно (обычно отключено у монстров без специального события)
    "chances": {"s": 50, "sp": 30, "e": 20} - В конфиге не нужны. Внутренний накопитель шансов при прокрутке действия

    s - stairs. Шанс выбора лестницы.
    sp - special. Шанс выбора специального события (далее в тексте возможен спешл)
    e - else. Шанс выбора других кабинетов

Работа монстра - каждый тик игры (1 реальная секунда) вызывается monster.update
Апдейт проходится по всем бихейверам и вызывает их апдейт
    Каждый бихейвер обновляет данные монстра и/или monster state. Сам монстр доверяет бихейверам и совершает действия относительно своего state

export type MonsterState =
    | "idle" - Монстр стоит и ожидает действия
    | "moving" - Монстр передвигается по корридору
    | "watching" - Монстр смотрит на камеру. Событие возможно при открытии камеры на которой будет монстр. Он изменит состояние на watching и несколько секунд будет занят тем что смотрит на камеру
    | "special" - Монстр совершает специальное действие. Обычно в это время игрок должен поиграть в миниигру. В это время монстр не двигается и находится в месте где активировал спешл
    | "attacking" - Монстр дошел до игрока в кабинет (отрисовываться от будет в коридоре у двери но програмно будет находиться в аудитории). Происходит скример (игра окончена)
    | "returning"; - Монстр возвращается на стартовую точку (будет происходить почти мгновенно но изменять состояние все равно надо)

В некоторых ситуациях, как например при watching или special монстр не будет двигаться пока не изменит своё состояние. Для упрощения можно выделить на watching 4 тика (4 секунды).
Спешл же управляется сигналами и будет завершен когда придет monitor:minigame-pending-end так что устанавливать тики необязательно, достаточно events.on...

У монстра помимо default_target существует также quick_target. Это быстрая точка на которую монстр идёт в пределах этажа
Она выбирается рандомно путём прокрутки chances
Если sp > 50 то сначала крутится его шанс а затем уже лестницы
иначе крутится сначала лестница а затем спешл
В противном случае выпадает обычный кабинет (если не выпала лестница и спешл)
У монстра есть monster intelligence
Монстр идёт по пути с шансом 10*intelligence процентов на тик.
Его путь определяется файлами комнат 

Пример файла
{
    "id": "1f.2s", - id комнаты
    "name": "Дальняя лестница 1 этажа", - название для камер
    "ways": {
        "2f.2s": 1 - возможные пути из комнаты и длинна в шагах
    },
    "cameras": {
        "2f.2s.1": {"active": true} - то какие камеры есть на этаже
    },
    "spots": [
        {"id": "door"} - точки в которых монстр может стоять на камере
    ],
    "isSpecial": false - можно ли активировать спешл в комнате
}

При смене комнаты монстр должен также определить на какой камере он появится (камер может быть несколько) и спот на котором он будет стоять
По умолчанию парадная лестница 1s, дальняя 2s. Коридор c а спортзал s. Кабинеты имеют в названии свой номер
Этаж помечается как nf где n - номер этажа.
Таким образом
Кабинет 1f.103
Камера в кабинете 1f.103.1
Layer изображения на камере в кабинете 1f.103.1.computer

При движении к quick_target или default_target (могут совпасть, главное каждый раз проверять достиг ли ты default_target) состояние монстра изменяется на moving
Про другие состояния мы поговорили. Также у монстра есть такие служебные параметры как
    readonly id: string;
    readonly name: string;

    intelligence: number = 0;

    state: MonsterState = "idle";

    startRoom: string;
    currentRoom: string;

    spot: string | null = null;

    pose: string | null = "default";
    targetRoom: string | null = null;
    quickTarget: string | null = null;


    behaviors: IBehavior[] = [];

Поза пока не используется но возможно добавится позже для анимаций микроскримера на камерах или разных расположений на спотах
Еще несколько деталей. После завершения специального события chances сбрасываются до дефолтных из конфига. При неудачной атаке монстра (состояние moving - returning - idle, без atacking) монстр возвращается на стартовую позицию

Как работает "qte_special" для монстра
QTE special - специальная способность монстра "Клт". На камере 414 кабинета активируется кнопка, которую нужно успеть нажать в течение 30 секунд
Если не нажимать кнопку миниигра засчитается как провальная
При нажатии кнопки активируется миниигра. В ней необходимо за отведенное время ввести определенное слово без ошибок
При проигрыше миниигра засчитывается как провальная
При провале игры все камеры деактивируются на 1 час

Как работает "rock-paper-scissors"
Миниигра активируется с шансом 70% после успешно пройденной ночи
